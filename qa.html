What this evidence is — and is not

Synthetic data, mock integrations. The product is a single-file prototype: provider responses, latencies and settlement files are deterministic simulation, not a real payment backend. These results validate the mock implementation and its tested UI behaviour only.
Functional verification, not usability research. Scripted executions measure whether defined assertions hold in this build; they are not user research, production reliability data, revenue/loss-prevention evidence, or model validation.
Intentional probes excluded. The acceptance probe (M01) deliberately asserts a false statement to prove failures surface; it is excluded from every product metric above and reported in its own section.
Persistence: runs are stored on this machine under qa/results/runs/ (JSON) with screenshots/traces per failure — they survive a refresh. Deploying only the static page to a host cannot launch a visible browser there: run the local runner (cd qa && npm install && npm start) and open /qa.
